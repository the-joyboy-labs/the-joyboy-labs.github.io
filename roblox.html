// FEATURED PATTERN

A server-checked coin pickup

Keep rewards on the server. This example checks the triggering player, their distance, and a short cooldown before changing a value.

PATTERN 01 / SERVER SCRIPT

Reward a player through a ProximityPrompt

Place a Script in ServerScriptService and add a ProximityPrompt named CoinPrompt under a BasePart or Attachment in Workspace.

LUAU
ServerScriptService / CoinPickup.server.lua
local Players = game:GetService("Players")
local prompt = workspace:WaitForChild("CoinPrompt")
local COIN_REWARD = 5
local MAX_DISTANCE = prompt.MaxActivationDistance + 2
local cooldowns = {}

local function awardCoins(player)
    if not player or player.Parent ~= Players then
        return
    end

    local character = player.Character
    local root = character and character:FindFirstChild("HumanoidRootPart")
    local promptPart = prompt.Parent

    if promptPart and promptPart:IsA("Attachment") then
        promptPart = promptPart.Parent
    end
    if not root or not promptPart or not promptPart:IsA("BasePart") then
        return
    end
    if (root.Position - promptPart.Position).Magnitude > MAX_DISTANCE then
        return
    end

    local now = os.clock()
    if cooldowns[player] and now - cooldowns[player] < 1 then
        return
    end
    cooldowns[player] = now

    local leaderstats = player:FindFirstChild("leaderstats")
    local coins = leaderstats and leaderstats:FindFirstChild("Coins")
    if coins and coins:IsA("IntValue") then
        coins.Value += COIN_REWARD
    end
end

Players.PlayerRemoving:Connect(function(player)
    cooldowns[player] = nil
end)
prompt.Triggered:Connect(awardCoins)
i

Example assumes your game creates leaderstats.Coins. Keep important game state and reward decisions on the server, and test changes in a private Studio session first.

Good habits, built in.

A few dependable rules make game systems easier to maintain and harder to abuse.

A / AUTHORITY

Trust the server

Let the server validate important actions and own rewards, inventory, and progression.

B / VALIDATION

Check every request

Verify types, distance, cooldowns, and game state before applying a change.

C / ITERATION

Test in Studio

Use separate test sessions and clear output logs to catch issues early.
